## 看板状态

每条任务使用以下状态：

- `待处理`：还没有开始。
- `处理中`：Agent 正在整理或修改。
- `待确认`：需要用户、老板或同事确认资料。
- `待验收`：已经完成，等主控 Agent 或用户看页面。
- `已通过`：可进入老板验收版。
- `后置优化`：不影响当前验收，留到二阶段。

## 问题严重度

- `P0`：会误导客户或老板，必须修。例如错船名、错日期、错价格、错航线图。
- `P1`：明显影响观感或理解，老板验收前建议修。例如移动端错位、图片很弱、文案堆砌。
- `P2`：体验优化，不阻断老板看。例如动效、细节间距、二级文案。

## 单船票专项规则

单船票页面不是普通产品列表，也不是同事文档展示页。它必须让客户完成这条理解路径：

1. 我知道什么是单船票。
2. 我知道自己适不适合只买船票。
3. 我能按船司、航线、月份、天数、政策缩小范围。
4. 我知道哪些是官网已有明确产品，哪些需要顾问实时确认。
5. 我能提交需求或咨询某个航次。

## 每轮工作节奏

1. 主控 Agent 确认本轮目标。
2. 专项 Agent 分头检查，不跨职责乱改。
3. 产品 Agent 先处理单船票相关任务。
4. QA Agent 跑命令和页面抽查。
5. 主控 Agent 给出老板验收结论。
