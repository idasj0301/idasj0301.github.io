# 产品 Agent 专项：单船票页面

## 任务定位

单船票是产品 Agent 当前第一优先级。页面目标不是展示库存，而是建立一个清楚、可信、适合咨询转化的单船票业务入口。

## 业务定义

单船票指客户只购买邮轮或探险船航段，通常适合已经自行安排国际机票、签证、前后段住宿或岸上行程的客人。

页面必须明确：最终价格、舱位、库存、优惠政策和包含项目，以顾问和船司实时确认为准。

## 页面必须回答的问题

- 什么是单船票？
- 单船票和跟团产品有什么区别？
- 单船票适合哪些客人？
- 船客能帮客户解决什么？
- 客户可以按哪些条件找船票？
- 哪些船司是船客重点合作资源？
- 为什么价格和余舱需要实时确认？
- 已经有机票和签证，能不能只订船票？

## 筛选维度

页面筛选维度固定为：

- 目的地：南极、北极、格陵兰、加拉帕戈斯、其他
- 船司：庞洛、银海、夸克、66度、A21、SWAN、OW、信天翁、欧若拉
- 出发月份
- 航程天数
- 船名
- 特殊政策：免单房差、早鸟、尾舱、闪促、转让

筛选结果表述为“可咨询航线”，不表述为“现货库存”。

## 产品卡字段

单船票产品卡至少包含：

- 标题
- 船司 / 船名
- 目的地
- 出发日期或月份
- 天数
- 舱型提示
- 政策标签
- 价格展示
- CTA：询问该航次

价格规则：

- 有明确价格：使用 `¥xx 起`、`€xx 起` 等现有价格标签。
- 无明确价格：使用 `顾问实时确认`。

## 页面结构建议

1. 首屏：单船票标题、核心说明、提交需求 CTA、咨询实时余舱 CTA。
2. 核心解释：什么是单船票、适合谁、船客优势。
3. 合作船司：按固定顺序展示重点船司。
4. 热门咨询方向：银海 Top 5 等待真实资料补齐。
5. 查找船票：筛选维度 + 可咨询航线。
6. 官网在售单船票：项目内正式 ticket 产品。
7. FAQ：服务边界、包含/不包含、实时价格原因。

## GEO / SEO 要求

- 页面标题必须包含“单船票”。
- 页面描述必须自然包含“按船司、航线、档期、舱位政策匹配”。
- FAQ 必须覆盖客户常见问题。
- `llms.txt` 后续应补充单船票说明，而不只写“按航次购买船票”。

## 验收标准

- 客户能在 30 秒内理解单船票业务。
- 船司顺序符合业务优先级。
- 已有正式产品和待确认咨询方向区分清楚。
- 页面不出现假库存、假价格、错船司、错航线。
- 桌面端和移动端都可给老板看。
